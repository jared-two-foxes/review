# WI-1: Scoped process execution tool

## Outcome

A bounded, safe tool that executes a preconfigured command (not model-chosen)
and returns structured output. This is the foundational capability for
implement-cli role support — without it, no role can verify compilation or
test outcomes.

## Context

`implement-cli` currently has only file I/O tools (`read_file`,
`replace_file_content`, `get_project_guidance`). To serve as a tester (verify
test compiles and runs red) or developer (verify implementation compiles and
test runs green), the agent needs a way to execute a compile command and a
test command and observe the result.

This corresponds to the process executor element of Vertical 6 from the
platform plan, scoped to the implement-cli use case.

## Key design decisions

- **Two tools, not one generic tool.** `run_check` (executes the compile
  command) and `run_test` (executes the test command). Each takes no
  model-supplied arguments — the command comes from the request.
- **Commands are request-specified, not model-chosen.** The `ImplementRequest`
  carries `compile_command` and `test_command` as argument vectors (e.g.
  `["cargo", "build"]`). The tools execute only these commands.
- **No shell.** Commands are executed as argument vectors via
  `std::process::Command`, never through a shell string.
- **Safety properties (matching V6 spec):** working-directory confinement to
  repository root, timeout (default 120s), cancellation propagation, stdout/stderr
  bounded to 64KB each, exit code captured, output marked as untrusted content.
- **Outcome classification by exit code:** 0 = success, non-zero = failure.
  For `run_check`, exit 0 = compiled. For `run_test`, exit 0 = tests passed
  (green), non-zero = tests failed (red).
- **New capability marker: `ScopedExec`.** Added to `capabilities.rs` with
  `ToolAllowedIn<ScopedExec>` impls. `ReadOnly` and `ScopedWrite` catalogs
  cannot register these tools.

## Affected files

- `crates/code-agent-runtime/src/capabilities.rs` — add `ScopedExec` marker
- `crates/code-agent-runtime/src/tools.rs` — add `RunCheckTool`, `RunTestTool`
- `crates/code-agent-runtime/src/process.rs` (new) — process execution helper
  with timeout, output bounding, cancellation
- `crates/code-agent-runtime/src/lib.rs` — export new module
- `crates/implement-app/src/lib.rs` — register `run_check` and `run_test` in
  the catalog when the request carries compile/test commands

## Acceptance Criteria

- [ ] `RunCheckTool` executes the request-specified compile command and returns exit code + bounded stdout/stderr
- [ ] `RunTestTool` executes the request-specified test command and returns exit code + bounded stdout/stderr
- [ ] Neither tool accepts model-supplied command arguments
- [ ] stdout and stderr are each bounded to 64KB with truncation markers
- [ ] Timeout produces a `timed_out: true` result without hanging
- [ ] Cancellation token is checked before process spawn
- [ ] Process execution is confined to the repository working directory
- [ ] Commands are executed as argument vectors, never through a shell
- [ ] `CodeToolCatalog<ReadOnly>` cannot register `RunCheckTool` or `RunTestTool` (compile-fail test)
- [ ] `CodeToolCatalog<ScopedWrite>` cannot register them either (compile-fail test) — only `ScopedExec` catalogs can

## Dependencies

None — this is the foundational work item.
