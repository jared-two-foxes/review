# V2 — Path containment, symlink rejection, and output bounds

Implement the security policy layer that protects repository reads: path containment, symlink-escape rejection, sensitive-path policy, and byte/line output limits with truncation and completeness markers. This is the safety gate between git operations and the model.

## Acceptance Criteria
- [ ] Absolute paths and paths containing `..` segments that escape the repository root are rejected before any file access. Example: `read_file("/etc/passwd")` returns a denied result; `read_file("../../secret")` returns a denied result; `read_file("src/main.rs")` is allowed.
- [ ] Symlinks that resolve outside the repository root are rejected. Example: a symlink `src/link → /etc` is detected and denied; a symlink `src/link → ../other-dir` that stays within the repo is allowed (or denied depending on policy — the implementation must choose and document the choice).
- [ ] Sensitive paths matching a deny-list pattern are rejected. Example: `.git/config`, `.env`, `.env.local`, `**/.aws/credentials`, `**/id_rsa` are denied regardless of whether they exist; the denial does not reveal whether the file exists.
- [ ] File reads exceeding the byte limit are truncated with an explicit truncation marker. Example: a 100KB file with a 10KB limit returns the first 10KB followed by `\n[truncated: 10240 of 102400 bytes]`; the truncated result's `completeness` field is `false`.
- [ ] Directory listings exceeding the entry limit are truncated with an explicit truncation marker. Example: a directory with 500 entries and a 100-entry limit returns 100 entries followed by `[truncated: 100 of 500 entries]`.
- [ ] Search results exceeding the match limit are truncated with an explicit truncation marker, and the result's `completeness` field is `false` so the model cannot claim absence. Example: searching for `fn ` in a large file with a 50-match limit returns 50 matches with `[truncated: 50 matches, search incomplete]`.

### Context
- Depends on the repository operations ticket (provides root resolution and path canonicalization).
- Path containment: after canonicalization (from the repo operations ticket), verify the canonical path starts with the repository root prefix.
- Symlink detection: use `std::fs::symlink_metadata` to check if a path is a symlink, then resolve it and check if the target is within the repository root.
- Sensitive-path deny-list: a configurable list of glob patterns. V2 starts with a hardcoded list: `.git/**`, `.env*`, `**/.aws/**`, `**/id_rsa*`, `**/*.pem`, `**/*.key`.
- Byte limit: configurable, default 10KB per read. The limit applies to the raw content before any processing.
- Entry limit: configurable, default 100 entries per directory listing.
- Match limit: configurable, default 50 matches per search.
- Truncation markers must be machine-readable (part of the tool result, not just text).
- The `completeness` field on tool results is `true` when the full result fits within limits, `false` when truncated.
- This is the safety-critical layer — the model must never access files outside the repository or exceed output bounds.
