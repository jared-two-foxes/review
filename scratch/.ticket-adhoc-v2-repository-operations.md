# V2 — Repository operations and snapshot identity

Introduce the `code-agent-runtime` crate with git repository opening, commit resolution, and deterministic snapshot hashing. This is the foundation for all V2 repository tools — it provides the read-only git operations that the tools wrap.

## Acceptance Criteria
- [ ] Opening a local git repository resolves the repository root and canonicalizes paths relative to it. Example: opening `/path/to/repo` with a relative path `src/main.rs` produces the canonical path `/path/to/repo/src/main.rs`; a path `../escape` is rejected as outside the repository root.
- [ ] Resolving a base ref and head ref produces immutable commit identifiers that cannot change during a single review session. Example: resolving `fixture/base` and `fixture/bug` returns two commit hash strings; re-resolving the same refs within the same session returns identical identifiers.
- [ ] A snapshot identity is computed from the resolved commit range and is deterministic — the same base/head pair always produces the same snapshot ID. Example: snapshot ID is `sha256:{base_oid}:{head_oid}` or equivalent; two sessions reviewing the same range produce the same ID.
- [ ] Changed files between the base and head commits are enumerated with their status (added, modified, deleted, renamed). Example: a commit that adds `src/new.rs` and modifies `src/old.rs` returns `[("src/new.rs", "added"), ("src/old.rs", "modified")]`.
- [ ] Diffs for individual changed files are produced in a bounded, structured format with line numbers. Example: `read_diff("src/old.rs")` returns hunks with `@@ -10,3 +10,5 @@` markers; output exceeding the byte limit is truncated with an explicit truncation marker.

### Context
- Creates new crate `code-agent-runtime` per vertical plan §3 and §8 work item 1.
- Uses `git2` crate (libgit2 bindings) for repository operations — the standard Rust git library.
- Repository-root resolution: walk up from a given path until `.git` is found, or accept an explicit root.
- Path canonicalization: resolve relative paths against root, reject paths that escape the root via `..` or symlinks (symlink rejection is a separate ticket — this ticket handles canonicalization only).
- Commit resolution: use `git2::Repository::revparse_single` to resolve ref names to commit OIDs.
- Snapshot hashing: hash the base OID + head OID (not the full tree — that's expensive and unnecessary for identity).
- Diff model: use `git2::Diff` to compute changes between base and head trees; produce per-file hunks with line numbers.
- All operations are read-only — no writes to the repository, no index modifications, no worktree changes.
- Byte/line limits are applied at the tool level (next ticket), not at the repository operation level.
- Dependency: `agent-kernel` (for tool interfaces, if needed) — but this crate can be tested independently of the kernel by testing git operations directly.
