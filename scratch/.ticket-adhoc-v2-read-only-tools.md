# V2 — Six bounded read-only repository tools

Implement the six initial read-only repository tools as `Tool` trait implementations in `code-agent-runtime`, wrapping git operations with the security policy. Each tool produces content IDs and truncation markers on all observations.

## Acceptance Criteria
- [ ] `get_change_summary` returns a structured summary of the entire change: file count, total insertions, total deletions, and per-file status. Example: `{"files_changed": 3, "insertions": 45, "deletions": 12, "files": [{"path": "src/main.rs", "status": "modified"}, ...]}`.
- [ ] `get_changed_files` returns the list of changed files with their status and a content ID for each file's current version. Example: `[{"path": "src/main.rs", "status": "modified", "content_id": "sha256:abc123..."}]`.
- [ ] `read_diff` returns the diff for a specific changed file with line-numbered hunks, bounded by the byte limit. Example: `read_diff({"path": "src/main.rs"})` returns hunks with `@@ -10,3 +10,5 @@` markers; output over the limit is truncated.
- [ ] `read_file` returns the content of a file at the head commit, bounded by the byte limit, with a content ID. Example: `read_file({"path": "src/main.rs"})` returns `{"content": "fn main() {...}", "content_id": "sha256:...", "truncated": false, "completeness": true}`.
- [ ] `list_directory` returns directory entries with file/directory type indicators, bounded by the entry limit. Example: `list_directory({"path": "src"})` returns `[{"name": "main.rs", "type": "file"}, {"name": "utils", "type": "dir"}]`.
- [ ] `search_text` performs a literal (not regex) exact-match search and returns matches with file path, line number, and the matching line content, bounded by the match limit. A truncated search has `completeness: false` so the model cannot claim absence of matches. Example: `search_text({"query": "TODO"})` returns `[{"path": "src/main.rs", "line": 42, "content": "// TODO: fix this"}]`.

### Context
- Depends on repository operations (git) and path security (containment, limits) tickets.
- All six tools implement the `Tool` trait from `agent-kernel::tools`.
- Each tool's `description()` returns a `ToolDescription` with `input_schema` for strict validation.
- Each tool's `description()` must contain no mutation language — read-only intent only.
- Content IDs are SHA-256 hashes of the file content at the head commit (or the diff content for `read_diff`).
- The `search_text` tool uses literal string matching, not regex — regex is deferred to V8 per the plan.
- Exact-search completeness: if the search was truncated (hit the match limit before scanning all files), `completeness` is `false`. The model must not interpret a truncated search as "no more matches exist."
- Tools are registered in a `ToolCatalog` that the review application requests during initialization.
- All tool results include the snapshot ID from the repository operations layer, so all observations are linked to the same review session.
