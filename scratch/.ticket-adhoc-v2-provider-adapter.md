# V2 — Canonical model provider adapter

Implement one real model provider adapter that connects the kernel's `ModelProvider` trait to a production LLM API. The adapter handles request serialization, response parsing, deadline enforcement, and usage normalization without exposing provider-specific types to the review application.

## Acceptance Criteria
- [ ] The adapter implements `ModelProvider::generate` by serializing the canonical model request (instructions, context, tool descriptions) into the provider's API format and parsing the response back into `CanonicalModelResponse` with model actions. Example: the model receives the system instructions and tool catalog, and returns a `ToolCall` action that the coordinator dispatches.
- [ ] Provider failure (network error, timeout, API error, rate limit) produces a typed error that the coordinator maps to an indeterminate result — never an approval. Example: a connection timeout after 30 seconds returns an error; the coordinator catches it and the session ends with indeterminate status, not approved.
- [ ] Token usage is normalized into a structured `UsageRecord` with input tokens, output tokens, and estimated cost. Example: the adapter extracts `usage.prompt_tokens` and `usage.completion_tokens` from the API response and maps them to the canonical usage fields.
- [ ] A deadline parameter prevents unbounded model calls. Example: a 60-second deadline causes the adapter to abort the request and return an error if the provider has not responded within the deadline.
- [ ] No provider-specific types (request/response structs, error enums, authentication types) appear in the `agent-kernel` or `review-app` crates. Example: the provider's `ChatCompletion` struct lives only inside `code-agent-runtime`; the kernel only sees `CanonicalModelRequest` and `CanonicalModelResponse`.

### Context
- Depends on `agent-kernel` (for `ModelProvider` trait, `CanonicalModelRequest`, `CanonicalModelResponse`, `ModelAction`).
- The adapter lives in `code-agent-runtime` (or a separate `provider-adapter` crate if preferred).
- One provider only in V2 — likely OpenAI (most common) or Anthropic. The choice is implementation detail; the contract is the same.
- Uses `reqwest` or similar HTTP client for API calls.
- API key is provided via environment variable or configuration — never hardcoded.
- The adapter maps the provider's tool-calling format (e.g., OpenAI function calling) to the kernel's `ModelAction` enum.
- The adapter maps the provider's structured-output format to the kernel's `CanonicalModelResponse`.
- Provider-specific error types are caught and mapped to a generic error that the coordinator handles.
- The deadline is enforced via `reqwest`'s timeout or a `tokio` cancellation token.
- V7 (provider portability) will add a second adapter — this ticket only needs one.
