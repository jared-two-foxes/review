# V0 — Executable contract and repository bootstrap

Create a clean Cargo workspace with the minimal protocol and CLI crates so that `review run` accepts a versioned JSON request, validates it strictly, and emits a deterministic indeterminate result. No model or repository access exists yet; this establishes the process contract that later verticals build on.

## Acceptance Criteria
- [ ] `review run --request tests/fixtures/v0/minimal-request.json --format json` produces a schema-valid review result with an indeterminate status and a "review engine not available" reason, exiting with the indeterminate exit code.
- [ ] A request containing unknown fields, an unsupported major schema version, an invalid repository path, or duplicate JSON keys is rejected with a typed validation error and exits with the invalid-request exit code.
- [ ] In JSON output mode, stdout contains only the machine-readable result; all human log output goes to stderr.
- [ ] Re-running the same fixture request with a deterministic test clock and ID generator produces byte-identical output to a checked-in golden fixture.
- [ ] Exit codes are defined and emitted for approved, changes requested, indeterminate, invalid request, internal failure, and cancellation, even when only indeterminate and invalid request are currently producible.
- [ ] Generated schema files for the request, result, and error envelopes are checked into `schemas/review/`, and a CI check fails when generated files drift from the checked-in copies.
- [ ] An architecture decision record in `docs/decisions/` documents that the repository is greenfield, Scaffold integration is subprocess-only, and no crate in the workspace depends on Scaffold production code or uses foreign-language native bindings.

### Context
- Greenfield repo — no code exists yet. This ticket creates the entire Cargo workspace from scratch.
- Crates to create per vertical plan §3 and §6: `agent-protocol`, `review-protocol`, `review-app`, `review-cli`, `cli-common`.
- Dependency direction (vertical plan §3): `review-cli → review-app → review-protocol → agent-protocol`; `cli-common` holds shared CLI parsing, stdin/file input, and stdout/stderr separation.
- Protocol schema versions: `review.request/v1`, `review.result/v1`, error envelope `agent.error/v1` (kernel spec §22.1).
- Strict JSON deserialization with `#[serde(deny_unknown_fields)]` on request boundary types — unknown-field rejection is a hard invariant (vertical plan §6, §2.4).
- The V0 result is always `INDETERMINATE` with reason `REVIEW_ENGINE_NOT_AVAILABLE`; it must not pretend to approve a change (vertical plan §6 end-to-end demo).
- Test clock and ID generator are introduced as injectable traits so V1's deterministic golden tests are possible (vertical plan §6; V1 depends on this).
- Schema generation: use `schemars` or equivalent to derive JSON Schema from Rust types; the drift check compares generated output against the checked-in files in `schemas/review/`.
- Exit codes: a stable mapping for the six terminal states (approved, changes requested, indeterminate, invalid request, internal failure, cancellation). Exact numeric values are the implementer's choice but must be stable and documented. Only indeterminate and invalid request are producible in V0; the others are defined for forward use.
- CLI supports `review run --request <path> --format json` and `review run --request -` (stdin). Output to stdout in JSON mode; logs to stderr.
- Linux and Windows CI (GitHub Actions or equivalent) with a release-profile build. The schema-drift check and the no-Scaffold-import guard run in CI.
