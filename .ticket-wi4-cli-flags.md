# WI-4: CLI flags and request construction

## Outcome

`implement-cli` accepts new flags for role, compile command, and test command,
and constructs the extended `ImplementRequest` from them.

## Context

The current `implement-cli` accepts flag-based and file-based request
construction with `--repository`, `--target-path`, `--expected-content`,
`--desired-content`, and budget/model flags. To support role-based flows, new
flags are needed for the role and the compile/test commands introduced in WI-3.

## Key design decisions

- **New flags:**
  - `--role <tester|developer>` — optional, defaults to none (current behavior)
  - `--compile-command <CMD>` — a string split into an argument vector (e.g.
    `"cargo build"` → `["cargo", "build"]`)
  - `--test-command <CMD>` — same format, for the test command
  - These are also accepted in the `--request` JSON file (as
    `compile_command: ["cargo", "build"]` arrays)
- **Validation.** If `--role` is specified, both `--compile-command` and
  `--test-command` are required. If `--role` is absent, they are rejected if
  provided.
- **Help text.** Update the clap command definition and help output to document
  the new flags and their role requirements.

## Affected files

- `crates/implement-cli/src/main.rs` — flag parsing, request construction,
  validation, help text

## Acceptance Criteria

- [ ] `--role tester --compile-command "cargo build" --test-command "cargo test -- test_foo"` constructs a valid `ImplementRequest` with the role and commands
- [ ] `--role tester` without `--compile-command` or `--test-command` produces a typed validation error (exit code 2)
- [ ] A request JSON file with `role`, `compile_command`, and `test_command` fields is correctly parsed
- [ ] A request JSON file without the new fields (v0 format) is still accepted and produces the current behavior
- [ ] `implement-cli run --help` documents the new flags
