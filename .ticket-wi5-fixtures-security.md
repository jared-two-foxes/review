# WI-5: End-to-end fixtures and security hardening

## Outcome

Temporary-repository fixtures exercise the tester (red test) and developer
(green test) flows end to end, and security tests verify the process execution
boundary.

## Context

With WI-1 through WI-4 in place, implement-cli can serve as a tester and
developer in a TDD workflow. This work item provides end-to-end validation that
the complete flow works correctly, and verifies the security properties of the
new process execution tools.

## Key design decisions

- **Test fixtures.** Temporary repositories with a simple Rust crate (or shell
  script) where:
  - For the tester flow: an empty function stub that the test exercises. The
    test should fail (red) because the stub does nothing.
  - For the developer flow: a failing test already present. The implementation
    should make it pass (green).
- **Deterministic testing.** Use `ScriptedModelProvider` for all end-to-end
  tests so they are reproducible and don't require API keys. The scripted
  provider issues the expected tool calls (`read_file`,
  `replace_file_content`, `run_check`, `run_test`, completion).
- **Security tests.**
  - Model attempts to call `run_check` with arguments (rejected — tool takes
    no model arguments).
  - Compile command times out (verify `timed_out: true` and graceful handling).
  - stdout exceeds 64KB (verify truncation marker).
  - Process runs in the repository working directory, not an arbitrary path.

## Affected files

- `crates/implement-cli/tests/` — integration test fixtures and security tests

## Acceptance Criteria

- [ ] A scripted tester flow in a temporary repository produces a result with `status: CandidateReady`, `compiled: true`, `test_result: "failed"`
- [ ] A scripted developer flow in a temporary repository produces a result with `status: CandidateReady`, `compiled: true`, `test_result: "passed"`
- [ ] A scripted tester flow where the test accidentally passes (green) produces `status: Indeterminate` with a remediable rejection about the test not running red
- [ ] Process timeout produces a typed result without hanging
- [ ] Output bounding produces truncation markers at 64KB
- [ ] The model cannot supply command arguments to `run_check` or `run_test`
- [ ] All end-to-end tests use `ScriptedModelProvider` and are deterministic
